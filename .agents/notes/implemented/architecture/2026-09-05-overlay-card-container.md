# Agent Note: Reusable overlay card as the default frontend container

Status: implemented

English | [中文](2026-09-05-overlay-card-container.zh.md)

## Problem

Overlay frontend work is “write the page.” When the card chrome carries one product’s title and default size, the next product either looks like that product or occupies `shell.overlay` itself and reimplements title-bar drag plus eight-edge resize. That second window is the expensive path: chrome is not reusable, and a visualization package becomes a window plugin.

## Decision

[`@deepseek-ai/dsh-client-ui-float-window`](../../../../packages/client/ui-float-window/README.md) is the reusable overlay card desk. The browser half occupies `shell.overlay` as id `overlay-card` (order 220) and predeclares body slots `overlay-card.body` (seat 1) and `overlay-card-N.body` for N in 2..8, plus matching trailing lists. Chrome left is the title then the unique id from insert `--title` / `--card-id` (defaults `卡片` and the seat as a decimal string, so the first card still reads `卡片 1`). The slot seat is not that unique id. The title bar is 36px tall, overlays the body, and fades to transparent at its lower edge. Identity type stays the existing 13px chrome font. Trailing controls occupy that card’s list and do not start a drag. Built-in **缩小** (right of that list) collapses that window into an edge tag ([edge tag](2026-09-07-overlay-card-edge-tag.md)). Primary-button pointer down anywhere in the window (title bar, body, trailing chrome, or a resize handle) raises that card inside the desk and raises the desk in `ctx.overlayStack` ([overlay stack](2026-09-07-overlay-stack-and-card-plug.md)). The board uses `isolation: isolate` so card `z-index` stays inside the desk. Title-bar hover keeps the default cursor (not grab); resize handles keep resize cursors. Edge n/s/e/w handles keep an 8px layout box and receive pointer events only on the outer 4px strip so an 8px themed body scrollbar under the same edge stays clickable; corners keep the full 12px hit. The body is an independent webpage: product title, primary actions, and viewport live in the page occupant. Frames live in one desk store and persist in `localStorage` (`dsh.overlay-card.frames`) across a page reload, keyed by unique card id; `instances.json` still owns the roster, not live geometry. Insert `--width` / `--height` set first-mount size (defaults 360×280, the card minimum). A newly mounted card sits to the right of the current rightmost frame; when that opening size would leave the playable board, it overlaps the default origin so the title bar stays on the board ([playable board](2026-09-06-overlay-playable-board.md)). After that, `preferFrame`, drag, and resize change only that card's frame. Same-document `#id` links resolve inside that body ([isolation](2026-09-06-overlay-card-isolation.md)). A body slot with no occupant shows the filled `空卡片` label. A page may still call `preferFrame` on first mount; omit `x` / `y` to keep the current origin. After a stored frame, the first adopt, or a user drag/resize, later `preferFrame` calls no-op so a remount does not reset the window. `preferFrame` identity is stable so a page mount effect does not recreate the callback. Viewing flags such as pause are page-local React state. A tall branded title bar is an edit of `OverlayCard` in this package.

The node half serves `instances.list`, `instances.setHidden`, and `occupants.setInserted` on `/overlay-card` from `instances.json` next to the live plugin copy and the live profile patch. `rpc.handle` is called from `apply` (it already owns the route effect). Each roster entry is an `OverlayCardSpec` (`seat`, `id`, `title`, `width`, `height`, optional `hidden` and `occupants`). `hidden: true` keeps the spec in the file and skips desk mount; the desk also skips a spec whose occupant fibers are not inserted ([hide vs Loader disabled](2026-09-07-overlay-card-hide-and-loader-disabled.md)). The browser polls that roster so a second insert can add a window without remounting existing cards. A transport miss (SPA `405` when the channel is not mounted) keeps the last roster, which starts as the default first card. Host `lib/index.js` does not hot-swap: a live host-logic change needs a never-imported specifier, not a new `--id` under the same package name ([live path](2026-09-04-overlay-web-plugin-live-path.md)). Card insert writes `./overlay-card-roster-rpc.mjs` when the profile has no overlay-card RPC row so that specifier mounts `/overlay-card` ([roster channel](../bug-fix/2026-09-06-overlay-card-roster-channel.md)). `pnpm overlay:live insert packages/client/ui-float-window` writes the first spec (omitted flags take those defaults) and does not copy `lib/` again on a later insert of the same package. `--id` remains the Loader directory id. `pnpm overlay:live remove overlay-card-<id>` drops that unique id. `pnpm overlay:live remove ui-float-window` (or that Loader id) unloads the desk.

The published package name remains `@deepseek-ai/dsh-client-ui-float-window`; occupant identity is `overlay-card`. Pages type-import `…/client` for `SlotMap` and must not value-import `OverlayCard`. Default product pages occupy `overlay-card.body` (card 1).

The operational HOW for this **card** form is skill [dsh-overlay-web-plugins](../../../skills/dsh-overlay-web-plugins/SKILL.md): always insert the card module, write a page with `pnpm overlay:new-page <name>` ([page kit](../process/2026-09-05-overlay-new-page.md)), call `preferFrame` on mount (already in the kit), then `overlay:live insert|update` the page. Do not skip the card insert when a profile already shows a card. Do not clone another occupant or this card as the page package. Arbitrary-shape floaters and the full-page canvas are other forms ([form skills](../process/2026-09-05-overlay-frontend-form-skills.md)). Related notes: [live path](2026-09-04-overlay-web-plugin-live-path.md), [roster channel](../bug-fix/2026-09-06-overlay-card-roster-channel.md), [isolation](2026-09-06-overlay-card-isolation.md), [playable board](2026-09-06-overlay-playable-board.md), [edge tag](2026-09-07-overlay-card-edge-tag.md), [overlay stack](2026-09-07-overlay-stack-and-card-plug.md). Page occupants live in the [client plugin inventory](../../../../packages/client/README.md); each package README owns that occupant's description ([description registry](../process/2026-09-05-client-plugin-description-registry.md)).

## Alternatives considered

**Put the chrome in `ui-primitives`.** Rejected — the card needs slots, a register-declared store, and a Loader seat. Client plugins must not value-import another plugin’s components.

**Keep two window plugins (product-branded plus generic).** Rejected — pre-release prefers one card module; pages own product copy.

**Two Loader rows of the same npm package to spawn two browser cards.** Rejected — the client module graph is keyed by package name, so two yaml rows still run one browser `apply()`. Locale `(ns, locale)` cannot register twice. Slot names are globally unique. Numbered windows are instances inside one browser plugin, rostered by `instances.json`.

**Loader `config` for title and default size.** Rejected — `overlay:live` writes Loader `{ id, name }` only; the browser half does not receive Loader config. Title, unique id, and opening size are insert `--title` / `--card-id` / `--width` / `--height` stored on `OverlayCardSpec` in `instances.json`. A page `preferFrame` may still change size after mount. Users still drag-resize after that. Seat numbers remain slot names, not Loader config.

**Card reads occupant inject or `slots.entries()` to pick a size.** Rejected — slot components never see `ctx`; live data is owner props, local state, or a declared store. `preferFrame` is the owner callback.

**Write live `x` / `y` into `instances.json`.** Rejected — that file is insert-time roster plus `hidden` and `occupants`. Drag would need host RPC on every move. Browser `localStorage` matches the session rail and a page reload.

**Keep chrome and page in one package for visualizations.** Rejected — chrome belongs on the reusable card; a product package that copies title-bar drag and eight-edge resize is the expensive path.

**Rename the npm package.** Rejected — occupant identity is `overlay-card`; a directory rename is a host-side workspace install, not required for the slot contract.

**Declare the whole title bar as a replaceable single slot.** Rejected — move capture lives on `OverlayCard`; replacing the bar would drop drag unless the occupant reimplements it. Trailing list is the control hole. A tall bar is an edit of `OverlayCard` in this package.

**Raise only from title-bar or resize pointer down.** Rejected — pointer down in the body is attention in that window and must raise it too.

**Raise from a bubble-phase listener on the window.** Rejected — trailing chrome stops propagation so those clicks would miss. Capture on the window uses the same primary-button check as title-bar drag.

## Consequences

Frontend-only **card** overlay work is: insert the card (with optional title, unique id, and opening size), write a page for `overlay-card.body` (or `overlay-card-N.body`), optionally call `preferFrame` on mount. Each body slot is `kind: 'single'` — one page occupant per card. Unload `overlay-card-<id>` to drop one window; unload the Loader id to drop the desk. A body occupant may be a full interactive page (in-page navigation, forms, local React state); that is still this slot, not a second presentation form, and does not earn a per-occupant Agent Note. The page-canvas form is a reserved skill; this note does not author it. Card frames persist in `localStorage` across a page reload; clearing site data restores insert placement.

## Testing

The card package covers title-bar drag, eight-edge resize (n/s/e/w hit is the outer 4px strip), minimum frame, a 36px overlay title bar with the existing 13px identity font, insert-time title/id/size, `preferFrame` applying size (and optional origin) without moving other seats, a later `preferFrame` ignored after the first adopt or a stored frame, identity `{title} {id}`, trailing chrome that does not start a move, built-in 缩小 collapsing the card into an edge tag, primary-button pointer down in the body or trailing chrome raising that card without moving it, a second window that keeps the first frame, in-body hash resolution, the empty-body label, host `instances.list` including the `/overlay-card` prefix on `webServer`, roster poll that keeps the last snapshot when RPC throws, and `overlay:live` add/remove of `overlay-card-<id>` plus writing `./overlay-card-roster-rpc.mjs` when the roster channel is missing. Named gap: no automated test that two live page plugins cannot share `overlay-card.body`; `kind: 'single'` is the pin.
